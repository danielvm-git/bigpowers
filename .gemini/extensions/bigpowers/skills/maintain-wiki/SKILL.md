# Maintain Wiki

> **HARD GATE** — Never edit an OKF concept to say something the canonical source doesn't. OKF is derived, not authoritative — every concept body MUST cite its source. When QUERY returns a concept whose source_lines don't match the current source, treat the concept as stale and re-INGEST before trusting it.

## Overview

Maintain the Tier 0 codebase wiki — three OKF bundles (skills-wiki, conventions-wiki, agent-guide) generated by the OKF pipeline (e39s04/s05/s06). This skill is language-agnostic and agent-maintained. It replaces ad-hoc wiki upkeep with structured INGEST → QUERY → LINT operations.

## INGEST — Read Source → Write/Update OKF Concepts

**Purpose:** After changing a canonical source (SKILL.md, CONVENTIONS.md, CLAUDE.md), update the derived OKF concepts so the wiki stays current.

### Process

1. **Identify the source** — which canonical file changed? Which bundle(s) does it feed?
2. **Read the source** — load the full canonical file.
3. **Map source sections to concepts** — each section/heading/skill maps to one OKF concept page. For skills-wiki, one new skill = one new concept. For conventions-wiki, changed sections = changed concepts. For agent-guide, changed CLAUDE.md sections = changed concepts.
4. **Write/update concept files** — for each affected concept:
   - **skills-wiki concept** (`specs/skills-wiki/skills/<name>.md`): frontmatter with `okf_kind: concept`, `type: Skill`, `id`, `title`, `name`, `category`, `model`, `effort`, `phase`, `description`, `references[]`. Body: title, metadata, description, provenance line (`Auto-generated by sync-skills.sh --okf`).
   - **conventions-wiki concept** (`specs/conventions-wiki/<slug>.md`): frontmatter with `type: Convention`, `name`, `title`, `source`, `source_lines`. Body: title, provenance block citing CONVENTIONS.md section and line range, enforcer list with links to skills-wiki, attribution line.
   - **agent-guide concept** (`specs/agent-guide/<slug>.md`): frontmatter with `okf_kind: agent-guide`, `type: Guide`, `id`, `title`, `source`, `source_lines`, `generated_at`, `generator`. Body: title, `See: CLAUDE.md §X (lines Y-Z)` + one-line description.
5. **Update cross-references** — add/update `references[]` in related concepts that link to the changed concept. Check all bundles for stale links.
6. **Update index.md** — add/update the concept entry in the bundle's index. Ensure the navigation table and concept list reflect the current state.
7. **Update log.md** (if present) — append an entry: date, operation, source changed, concepts touched.
8. **Validate** — run `scripts/validate-okf.sh --dir specs/<bundle>/` on the affected bundle.

→ verify: `scripts/validate-okf.sh --dir specs/<bundle>/` exits 0 and all concepts report PASS.

### Regeneration shortcuts

For bulk changes, prefer the generator scripts over manual INGEST:
- Skills: `./scripts/sync-skills.sh --okf`
- Conventions: `./scripts/decompose-conventions.sh`
- Agent guide: `./scripts/generate-agent-guide.sh`

Use manual INGEST only for targeted updates (single skill added, single convention changed).

## QUERY — Search Index → Drill → Synthesize with Citations

**Purpose:** Answer architectural and procedural questions by traversing the OKF knowledge graph without re-reading the full canonical sources.

### Process

1. **Search the index** — read the relevant bundle's `index.md` (or all three for broad queries). Use the navigation table to identify candidate concepts.
2. **Drill into concepts** — read the candidate concept pages. Follow `references[]` cross-references to related concepts for context.
3. **Verify staleness** — for each concept read, compare `source_lines` against the current canonical source. If the source has changed since generation, warn the caller and either re-INGEST or flag as potentially stale.
4. **Synthesize answer** — compose a response that:
   - Answers the question directly
   - Cites specific concepts with file paths
   - Cites canonical sources where relevant (e.g., "per CONVENTIONS.md §Tests lines 193–203")
   - Notes any stale concepts discovered
5. **Format output** — use this structure:
   ```
   ## Answer
   [Direct answer]
   
   ## Sources
   - [concept path]: [key claim]
   - [canonical source]: [relevant excerpt]
   
   ## Cross-references
   - [related concept]: [how it connects]
   
   ## Staleness Warnings (if any)
   - [concept]: source changed at [date], concept may be stale
   ```

→ verify: every claim has at least one citation (concept path or source file + line).

## LINT — Contradictions, Stale Claims, Orphans, Missing Cross-References

**Purpose:** Check the integrity of the OKF knowledge graph and produce a lint report.

### Process

1. **Stale claims** — for each concept in all three bundles, compare `source_lines` against the current canonical source file modification time. Flag any concept where the source file's mtime is newer than the concept's `generated_at` or attribution date.
   ```bash
   # Example check: is source newer than concept?
   [ "$(stat -f %m "$SOURCE")" -gt "$(stat -f %m "$CONCEPT")" ] && echo "STALE: $CONCEPT"
   ```
2. **Contradictions** — compare concepts that reference the same subject (e.g., two skills claiming different models for the same task, a convention concept contradicting an agent-guide concept). Flag any conflicting claims. STRATEGY: group concepts by overlapping `references[]` targets; within each group, diff body claims for conflicts.
3. **Orphan pages** — find concept files that have NO incoming cross-references from any other concept (not counting index.md). Flag orphan concepts.
   ```bash
   # Check if any concept references this one
   grep -r "concept: <id>" specs/skills-wiki/ specs/conventions-wiki/ specs/agent-guide/ | grep -v "index.md"
   ```
4. **Missing cross-references** — for each concept that mentions another concept by name but doesn't list it in `references[]`, flag the missing link.
5. **Broken links** — verify every `references[].concept` value and every markdown link resolves to an existing file. Flag broken links.
6. **Data gaps** — check required frontmatter fields per concept type (see INGEST section for per-type field requirements). Flag missing fields.
7. **Produce lint report** — write `specs/lint-report.md`:
   ```
   ## Lint Report — [date]
   
   ### Stale Claims ([N])
   - [concept]: source modified [date], concept from [date]
   
   ### Contradictions ([N])
   - [concept A] vs [concept B]: [conflicting claim]
   
   ### Orphans ([N])
   - [concept]: no incoming references
   
   ### Missing Cross-References ([N])
   - [concept] mentions [other] without listing in references[]
   
   ### Broken Links ([N])
   - [concept] → [target]: file not found
   
   ### Data Gaps ([N])
   - [concept]: missing field [field]
   
   ## Summary
   [N] issues total: [N] stale, [N] contradictions, [N] orphans, [N] missing refs, [N] broken, [N] gaps
   ```

→ verify: `test -f specs/lint-report.md && echo OK`

## Common Pitfalls

1. **Editing OKF directly instead of the source.** OKF is derived. If a concept is wrong, fix the canonical source (SKILL.md, CONVENTIONS.md, CLAUDE.md) and re-INGEST — never patch the OKF file directly.
2. **INGEST without updating cross-references.** Adding a concept that other concepts should reference but not adding the `references[]` entry creates drift. Always check both directions.
3. **QUERY without staleness check.** A concept whose source has changed may be wrong. Always compare mtimes before trusting.
4. **LINT without acting on findings.** The lint report is actionable — the agent should fix issues found, not just report them.
5. **Forgetting to update index.md.** Adding a concept without updating the index makes it undiscoverable via QUERY.
