# Run Benchmark

> **HARD GATE** — Do NOT use benchmark scores to declare a skill "good" or "bad" in isolation. Benchmarks measure relative quality vs. a baseline — they catch regressions, they do not certify correctness.

Reads benchmark definitions from `specs/benchmarks/`, executes each scenario's grader with and without the skill loaded, and writes a structured `pass@k` report with delta grading that `evolve-skill` consumes.

## With/Without-Skill Delta Grading

Every scenario runs twice: once **with** the skill loaded (the skill under test is active in the agent's context) and once **without** (a bare agent with only CLAUDE.md). The delta `Δ = pass@k_with − pass@k_without` isolates the skill's causal contribution to quality. A negative delta is a regression flag.

## Train/Validation Split

Benchmark definitions partition scenarios into two sets:

| Set | Tag | Purpose |
|-----|-----|---------|
| **Train** | `split: train` | Development scenarios — used while iterating on the skill. Hitting 100% on train is expected. |
| **Validation** | `split: validation` | Held-out scenarios — the real quality signal. Overfitting train while validation stagnates is a design smell. |

`pass@k` is reported separately for train and validation. The validation score is the authoritative metric; train score is for iteration guidance only.

## Usage

```bash
# Benchmark a single skill
run-benchmark <skill-name>

# Benchmark all skills with definitions
run-benchmark --all

# Pin current results as baseline
run-benchmark <skill-name> --baseline
```

## Process

1. **Locate definition** — Read `specs/benchmarks/&lt;skill>.yaml`. If absent, report: `"No benchmark definition found for &lt;skill>. Create specs/benchmarks/&lt;skill>.yaml first."` and stop.

2. **Partition scenarios** — Split `scenarios[]` by `split` field:
   - `split: train` → training set (iteration guidance)
   - `split: validation` → validation set (authoritative metric)
   - No `split` field → defaults to `validation` (conservative default)

3. **Run each scenario (N-run delta)** — For each scenario in both train and validation sets:
   - Run the grader **N times** (default 3, configurable via `runs:` field in benchmark definition) in two modes:
     - **Without skill:** Agent loaded with only CLAUDE.md/CONVENTIONS.md — no skill under test.
     - **With skill:** Agent loaded with the skill under test active.
   - **Code grader:** Run `grader.command` in repo root via `bash -c`. Exit 0 → PASS. Non-zero → FAIL. Timeout: 15 seconds.
   - **Rubric grader:** Present each criterion to the agent as a yes/no question about the scenario output. ≥ 80% yes → PASS, else FAIL.
   - Record per-run results in a results matrix: `{scenario_id: {with: [P/F, ...], without: [P/F, ...]}}`.

4. **Calculate scores** — For each split (train, validation) and each mode (with, without):
   - `pass_rate = sum(pass_count) / total_runs` across all scenarios in the split.
   - `pass@k = sum(weight × pass_rate for each scenario) / sum(all weights)`.
   - `Δ = pass@k_with − pass@k_without` — the skill's causal quality contribution.
   - Round all scores to 2 decimal places.

5. **Write benchmark.json** — Machine-readable aggregate output alongside the YAML report:
   ```json
   {
     "skill": "survey-context",
     "run_date": "2026-06-22",
     "runs_per_scenario": 3,
     "train": {
       "with_skill": 0.92,
       "without_skill": 0.67,
       "delta": 0.25,
       "scenarios": ["s01", "s02"]
     },
     "validation": {
       "with_skill": 0.83,
       "without_skill": 0.60,
       "delta": 0.23,
       "scenarios": ["s03", "s04", "s05"]
     }
   }
   ```
   Write to `specs/benchmarks/reports/benchmark-&lt;skill>.json`. Delta &lt; 0.0 flags a regression.

6. **Write YAML report** to `specs/benchmarks/reports/BENCHMARK-&lt;skill>-&lt;YYYY-MM-DD>.yaml`:

```yaml
skill: survey-context
run_date: "2026-06-22"
pass_at_k: 0.83
total_scenarios: 3
passed: 2
failed: 1
scenarios:
  - id: s01
    name: "detects active epic from state.yaml"
    result: PASS
    weight: 1.0
  - id: s02
    name: "reads release-plan.yaml and reports next epic"
    result: PASS
    weight: 1.0
  - id: s03
    name: "handles missing state.yaml gracefully"
    result: FAIL
    weight: 0.5
    failure_note: "crashed instead of suggesting state.yaml creation"
```

5. **Baseline mode** (`--baseline`) — Copy the report to `specs/benchmarks/reports/BASELINE-&lt;skill>.yaml`. This is the reference point for regression checks in `evolve-skill`.

6. **Compare to baseline** — If a `BASELINE-&lt;skill>.yaml` exists, compare `pass_at_k`. Report:
   - `IMPROVED: 0.67 → 0.83`
   - `REGRESSION: 0.83 → 0.67 — do NOT ship this change`
   - `STABLE: 0.83 = 0.83`
