# BUG-2026-07-02T103911: npm install fails on macOS — bash 3.2 lacks declare -A

## Problem

`npm install -g bigpowers` fails on macOS with:

```
/scripts/generate-skill-index.sh: line 17: declare: -A: invalid option
sync-skills: FAIL — SKILL-INDEX.md generation failed
```

- **Actual**: `postinstall` → `sync-skills.sh` → `generate-skill-index.sh` crashes because `declare -A` (associative arrays) requires bash 4.0+, and macOS ships bash 3.2.
- **Expected**: Install succeeds on any platform with a POSIX-compatible shell, including stock macOS.
- **Reproduction**: Run `npm install -g bigpowers` on macOS. Alternatively, `/bin/bash scripts/generate-skill-index.sh`.
- **Security impact**: NONE — build-tooling incompatibility, no exploit path.
- **GitHub issue**: #30

## Root Cause Analysis

The `generate-skill-index.sh` script uses `declare -A PHASE_MAP` (bash 4.0+ associative arrays) to map each of 70+ skills to a lifecycle phase ("Discover", "Design", "Plan", "Build", "Verify", "Release", "Sustain"). macOS ships bash 3.2 where `declare -A` does not exist.

The install chain is: `npm postinstall` → `sync-skills.sh` → `generate-skill-index.sh`. The `sync-skills.sh` script gates on `generate-skill-index.sh` exit code (`|| { echo "sync-skills: FAIL ..."; exit 1; }`), so the failure cascades up to npm.

A secondary fragility also exists: `regenerate-lockfile.sh` uses `sha256sum` (GNU coreutils), which is not native to macOS. This happened to succeed on the reporter's machine (likely Homebrew coreutils installed), but is another macOS-incompatible dependency.

**Risk level: High** — blocks all macOS users without bash 4+ from installing bigpowers.

## TDD Fix Plan

### Fix 1: Replace associative array in generate-skill-index.sh

1. **RED**: Run `generate-skill-index.sh` with system `/bin/bash` (3.2 on macOS) — fails with `declare: -A: invalid option`.
   **GREEN**: Replace `declare -A PHASE_MAP` and the associative array literal with a `get_phase()` function using a `case` statement. Change `${PHASE_MAP[$name]:-}` calls to `$(get_phase "$name")`.
   **verify**: `/bin/bash scripts/generate-skill-index.sh` exits 0 and produces SKILL-INDEX.md.

2. **RED**: `sync-skills.sh` (which calls `generate-skill-index.sh`) exits non-zero on failure. With bash 3.2, it should now succeed.
   **GREEN**: No code change needed if Fix 1 is correct — verify end-to-end.
   **verify**: `/bin/bash scripts/sync-skills.sh` exits 0.

3. **REFACTOR**: None needed — the `case` statement is functionally identical to the associative array and is actually simpler (no bash version dependency).

### Fix 2 (separate, secondary): Make regenerate-lockfile.sh macOS-compatible

4. **RED**: `regenerate-lockfile.sh` uses `sha256sum` which is absent on stock macOS.
   **GREEN**: Add a `sha256()` helper that prefers `sha256sum` but falls back to `shasum -a 256`.
   **verify**: Run `regenerate-lockfile.sh` on a macOS machine without GNU coreutils; exits 0.

## Resolution

**Fixed:** 2026-07-02
**Root cause confirmed:** `declare -A` (bash 4.0+ associative arrays) in install-chain scripts fails on macOS default bash 3.2.
**Fix applied:** Replaced `declare -A PHASE_MAP` in `generate-skill-index.sh` with a `get_phase()` case function; same fix applied to `add-model-frontmatter.sh`. Added `sha256sum`/`shasum` fallback in `regenerate-lockfile.sh`.
**Hardening added:** Regression guard in `sync-skills.sh` that fails the build if `declare -A` is reintroduced into install-chain scripts.
**Evidence:** `/bin/bash scripts/sync-skills.sh` exits 0 on macOS bash 3.2. SKILL-INDEX.md identical to pre-fix output.
**Commits:**
- `fix(scripts): replace declare -A with case for bash 3.2 macOS compatibility`
- `fix(scripts): replace declare -A in add-model-frontmatter, add bash-4 regression guard`
