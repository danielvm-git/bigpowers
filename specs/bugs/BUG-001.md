# BUG-001: Epic Status Drift

## Issue
Epics e28, e34, e38, e39, e40, and e47 are marked in the specs as `proposed` or `planned`, but they have already been implemented or outright merged via Pull Requests. The planning YAML state is out of sync with the git reality for these epics.

## RCA
- **Reproduction**: Run `python3 verify_epics.py` to check YAML vs Git status.
- **Isolation**: The drift is isolated to `specs/epics/e28-sync-pipeline-refactor/epic.yaml`, `specs/epics/archive/e34-context-engineering/epic.yaml`, `specs/epics/archive/e38-traceability-gate/epic.yaml`, `specs/epics/e39-semantic-context-bridge/epic.yaml`, `specs/epics/archive/e40-metrics-integrity/epic.yaml`, and `specs/epics/e47-global-install/epic.yaml`.
- **Hypothesis**: The epic YAML files were never updated to `done` after the PRs were merged, or they were archived prematurely.
- **Verify**: Fixing the status to `done` will correct the matrix.

## Fix
Update the `status` field in the respective `epic.yaml` files from `proposed`/`planned` to `done`.
