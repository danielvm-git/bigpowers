# BUG-2026-07-30T000000: install/update paths stay on the stale global version

## Problem

A user on an old global install (v2.75.2) followed the README to upgrade but stayed
on 2.75.2 despite the latest release being 2.87.0. The terminal shows `bigpowers update`
and `npx bigpowers setup` both re-running the 2.75.2 code.

**Expected:** the documented install/update commands land the newest published release.
**Actual:** every documented path silently keeps the stale globally-installed version.

## 4-Phase Root Cause Analysis

### Phase 1 — Reproduce
`bigpowers update` → banner reports v2.75.2 and re-syncs. `npx bigpowers setup` → also v2.75.2.

### Phase 2 — Isolate
Two independent mechanisms:

1. **`bigpowers update` never updates the package.** `bin/bigpowers.js` `update` branch
   only `require`s `setup.js` from `ROOT` (`.../node_modules/bigpowers`), the *already
   installed* copy. It runs the sync, never `npm install`. The help text even says
   "(after npm update -g bigpowers)" — but the command name implies self-update, so users
   run it alone and stay pinned.
2. **`npx bigpowers setup` reuses the stale global binary.** With bigpowers already global,
   `npx` prefers the installed binary over a registry fetch. Only `npx bigpowers@latest setup`
   forces the newest release.

Contributing: the README update flow lists `npm update -g bigpowers`, but `npm update -g`
does not reliably cross to `@latest` across npm versions. `npm install -g bigpowers@latest`
is the bulletproof form.

### Phase 3 — Hypothesize
`update` should self-update the global package before re-syncing; docs should pin `@latest`.

### Phase 4 — Verify
After the fix, `bigpowers update` on a global install runs `npm install -g bigpowers@latest`
then re-syncs the freshly installed version; non-global installs (git clone / npx temp)
print a clear note and skip the package self-update.

## Verify steps

1. `node bin/bigpowers.js help` exits 0 and lists commands.
2. From a non-global checkout, the self-update helper detects "not global" and skips the
   `npm install -g` step (no accidental global reinstall from a git clone).
3. README Quick Start, Update, and Reinstall use `@latest`-pinned commands.
