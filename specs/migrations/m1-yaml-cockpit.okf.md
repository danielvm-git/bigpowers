# M1: Markdown → YAML Cockpit (introduced in bigpowers v2.0.0)

## What changed

bigpowers v2.0.0 migrated from Markdown-based spec files to a structured YAML
cockpit. `STATE.md` became `state.yaml`, `RELEASE-PLAN.md` became
`release-plan.yaml`, and a new `execution-status.yaml` was introduced for
machine-readable story tracking. Fixed-name root-level spec files
(`SCOPE.md`, `CONTEXT.md`) were moved to subdirectories.

## What this migration does

1. **Heuristically parses `STATE.md`** → `state.yaml` using regex patterns.
   Fields like "Branch:", "Active flow:", "Current step:" are mapped to YAML keys.
   Prose sections that can't be parsed are preserved as YAML comments.

2. **Heuristically parses `RELEASE-PLAN.md`** → `release-plan.yaml`.

3. **Renames legacy files**: `SCOPE.md` → `product/SCOPE_LATEST.yaml`,
   `CONTEXT.md` → `tech-architecture/TECH_STACK_LATEST.md`.

4. **Creates `execution-status.yaml`** with empty scaffold.

5. **Adds missing v2.0.0 YAML keys** with safe defaults (`null`, `false`).

6. **Archives source files** to `specs/archive/` — never deletes originals.

## Manual steps after migration

- [ ] Review all ⚠ GUESS fields in `specs/state.yaml` — the heuristic parser
  may have misidentified prose sections. Check `active_flow`, `epic_cycle.*`,
  and `handoff.context` carefully.
- [ ] Review `specs/release-plan.yaml` — epic descriptions from Markdown prose
  may need restructuring into the YAML epic list format.
- [ ] Populate `specs/execution-status.yaml` with current story status.
- [ ] Delete `specs/archive/` directory once you've confirmed the migration
  is complete and correct.
- [ ] Run `bash scripts/sync-skills.sh` to regenerate agent artifacts.
