# T20 — impact-refactor-traceability

**Type:** Grilling (HITL) · **Status:** CLOSED · **Claim:** driver
**Blocks:** the last analysis-group documents in the survivor set · **Blocked by:** T1 (doctrine,
closed), T5 (pattern applied to all three)

## Question

Three documents, three skills (`assess-impact`, `plan-refactor`, `trace-requirement`) — do they
collide with each other (all touch "story ↔ code" mapping in some sense), and what does each
actually need?

## Resolution

**No collision between the three — different lifecycle moments, not competing formats.**
Verified against all three skill contracts: `assess-impact` is a **pre-change gate** (blast
radius of a *proposed* change, HARD GATE before `plan-work`); `plan-refactor` is an **interview-
driven delivery plan** (not analysis — Problem Statement/Solution/tiny-commit list); `trace-
requirement` is a **post-hoc coverage audit** (retrospective, periodic, whole-release-plan
scope). Different direction, different trigger, different scope — legitimate for all three to
touch code↔story mapping without being redundant, same reasoning as ADR/story not colliding.

**Naming pattern differs per document, confirmed against real files:**
- **IMPACT is per-target**, not a `_LATEST` singleton — 9 real live instances found
  (`IMPACT-e20-e20s01.md` … `IMPACT-e38-okf-adoption.md`), same pattern as ADR/TEST_PLAN.
  `IMPACT_LATEST.md` is vestigial, retired.
- **REFACTOR is a single evolving document** — no per-target siblings exist; refined in place
  like `scope.md`. `_LATEST` dropped per standing doctrine.
- **TRACEABILITY is a single tool-generated document** — but here I found **live drift**: two
  files existed simultaneously, `TRACEABILITY.md` (stale, manually-run, scope-limited to epics
  e01-e29, dated 2026-07-07, never referenced by `scripts/` or CI) and `TRACEABILITY_LATEST.md`
  (tool-generated by `trace-stories.sh`/`.py`, full-scope, dated 2026-07-19, the one CI actually
  runs). **`TRACEABILITY.md` is retired, not reconciled** — it was dead weight, not a second
  source of truth.

**Template grounded in the real generated output, not the skill's own documented shape** —
`trace-requirement`'s SKILL.md describes a simpler table than what the live file actually
contains (`TRACEABILITY_LATEST.md` has Coverage Summary counts + an "Oracle Stats" confidence
breakdown the skill doc doesn't mention). The tool evolved past its own documentation; the
template follows the tool, not the stale doc.
